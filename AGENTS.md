# AGENTS.md

Workspace guide for ZCode agents in the Dockpal repo — this is the canonical contributor
guide for editors/AIs. Facts below were verified against the repo, not inherited.

## What this is

Self-hosted Docker management panel: a **single Go binary** = Gin HTTP server + embedded
Svelte 5 SPA + BBolt database. Module `github.com/sdldev/dockpal`. Go 1.26 in `go.mod`
(CI pins 1.25 — keep both working).

Layout:

| Path | Contents |
|---|---|
| `main.go` | Wiring: data/log paths → BBolt → JWT secret → Docker client → health → agent mgr → metrics → routes → backup scheduler → audit retention. Also the CLI entry point. |
| `internal/` | Backend packages (see below) |
| `svelte/` | Svelte 5 SPA source (runes mode, TS, Tailwind 4, Vite 6) |
| `web/svelteDist/` | Vite build output, embedded via `go:embed` in `web/embed.go` — **gitignored, generated by `make svelte-embed`** |
| `templates/` | Deploy-preset JSON; runtime checks `./templates/` then `/opt/dockpal/templates` |
| `docs/svelte-migration/` | Per-phase notes from the Alpine.js → Svelte SPA migration |
| `.data/` | Dev runtime data (db, log, secret). Do **not** assume `/opt/dockpal/` exists locally. |

`internal/` packages: `server` (Gin setup, middleware, routes, RBAC, audit, WS/SSE),
`auth` (JWT + token-version checks, roles, password reset), `db` (BBolt), `agent`
(`AgentClient` interface — local/direct/WebSocket by instance ID), `docker` (moby
wrapper), `composecli` (Dockge-style stacks via the `docker compose` CLI plugin; its
`adapter` type exists to avoid an import cycle with `docker`, which defines the
`stackCLI` seam), `registry` (creds encrypted with a key derived from the JWT secret),
`health` (uses the injected `DBPinger` — never opens a second DB file), `backup`,
`metrics`, `git`, `ssh`, `traefik`, `tunnel`, `logging`, `validator`, `config`.

**Removed intentionally — do not re-add:** `internal/update` (self-update mechanism)
and the `dockpal-agent/` subdirectory (agent client code lives in `internal/agent/`).

## Commands

```bash
make build              # ./dockpal (version from git describe)
make prod-build         # svelte-embed + go build — what CI and releases run
make dev                # build + run on :3012, data in .data/
make dev-watch          # same, hot-reload on *.go via reflex (frontend still needs a rebuild)
make test               # go test -v ./...
make lint               # go vet ./...
make install-hooks      # pre-commit hook running vet + tests

make svelte-dev         # Vite on :5173, proxies /api (incl. WS) to :3012 — use this for SPA work
make svelte-build       # vite build → svelte/dist
make svelte-embed       # svelte-build + copy dist → web/svelteDist
make svelte-check       # svelte-check (TS type check)
make svelte-test        # vitest run
```

Focused tests:

```bash
go test ./internal/server -run TestName -v
go test ./internal/docker -run TestName -count=1   # bypass go test cache
```

Node 22 (`.nvmrc`, `svelte/package.json` engines) — vitest 4 dropped Node 20.

**Gotcha:** the Go binary only serves what is embedded in `web/svelteDist`. Editing
`svelte/` and running `make dev` changes nothing at `/` until you `make svelte-embed`
and rebuild. `make svelte-dev` is the loop that actually hot-reloads SPA changes.

## Architecture rules that matter for edits

- **New multi-instance features must go through the `AgentClient` interface** via
  instance-scoped routes (`/api/instances/:instance_id/...`), not the local Docker
  client directly. `InstanceMiddleware` resolves the instance, puts `agent_client` /
  `instance_id` / `database` / `registry_manager` in the Gin context, and returns 503
  for offline agents.
- Routes register in `internal/server/routes.go` via `RegisterRoutes(...)`. RBAC tiers:
  unauthenticated (`/api/login`, `/api/webhooks/deploy/:id`, `/api/config`, `/api/docs`,
  `/api/metrics`, health) → any authenticated user (reads) → Operator (container
  mutations, deploy, images, file writes, domains, registry, webhooks) → Admin (users,
  API keys, audit logs, backup trigger, roles, tunnel).
- WebSocket routes that can't send an `Authorization` header accept JWT via `?token=…`
  and still validate `Origin` against the request host.
- CLI subcommands (see `main.go`): `server`, `backup`, `restore`, `install`,
  `reset-password`, `rotate-secrets`, `version`, `help`. Default ports 3012 HTTP / 3443
  TLS (`PORT` to override). First startup auto-creates `admin` and logs a generated
  password; `DOCKPAL_INITIAL_ADMIN_PASSWORD` overrides it **only before the admin user
  exists** — it has no effect on later restarts or updates.

  | Variable | Default | Purpose |
  |---|---|---|
  | `DOCKPAL_DATA_DIR` | `/opt/dockpal/data` | Root for db, log, secret, backups |
  | `DOCKPAL_DB_PATH` | `<data>/dockpal.db` | BBolt database path |
  | `DOCKPAL_LOG_PATH` | `<data>/dockpal.log` | Rotating log path |
  | `DOCKPAL_SECRET_PATH` | `<data>/.secret` | JWT signing key file |
  | `JWT_SECRET` | — | Override JWT key directly |
  | `DOCKPAL_INITIAL_ADMIN_PASSWORD` | random | Bootstrap admin password (first startup only) |
  | `DOCKPAL_BACKUP_INTERVAL` | `24h` | Scheduled backup interval (`0` = off) |
  | `DOCKPAL_BACKUP_RETENTION` | `168h` | Backup retention window |
  | `DOCKPAL_AUDIT_LOG_RETENTION` | `2160h` | Audit log retention |
  | `DOCKPAL_TLS` | `false` | Enable TLS |
  | `DOCKPAL_TLS_CERT` / `DOCKPAL_TLS_KEY` | — | TLS cert/key paths |
  | `DOCKPAL_TLS_DOMAIN` | — | Domain for ACME auto-cert |
  | `DOCKPAL_AGENT_IMAGE` | — | Image for remote agent install commands |

## Frontend conventions

To add a page:

1. Create `svelte/src/components/pages/MyFeaturePage.svelte`
2. Import it and add a `$currentPage` branch in `svelte/src/App.svelte`
3. Add the page-id → path entry to `pagePaths` in `svelte/src/lib/router.ts`
4. Add a sidebar entry in `svelte/src/lib/store.ts` if it belongs in navigation

Navigate programmatically with `navigate(page, params)` from `lib/router.ts` — **not**
`currentPage.set(...)`, which desyncs the URL. Legacy Alpine paths (`/profile`,
`/registry`, `/deploy`, `/instances`, `/add-instance`) are aliased in `router.ts` so old
bookmarks keep working. The `$lib` alias must stay in sync between `vite.config.ts` and
`tsconfig.json`.

Reusable UI lives in `svelte/src/components/ui/` (`Button`, `Modal`, `ConfirmDialog`,
`Icon`) — prefer these over re-implementing; destructive actions go through
`ConfirmDialog` (see commits `6c8f8e5` / `7a3cbd1`). Deep links fall back to
`index.html` via the Gin `NoRoute` handler and resolve client-side.

## Testing notes

- Property tests use `pgregory.net/rapid`; baseline guidance in `scripts/pbt-baseline.txt`.
- Some tests require a running Docker daemon.
- `internal/health` tests use a `mockDB` implementing `DBPinger` — no real DB file opened.
- Run `make test && make lint` (plus `make svelte-check && make svelte-test` for SPA
  changes) before committing.

## Repo gotchas

- `.gitignore` anchors `/compose/` and `/repos/` (runtime scratch) — a previous
  unanchored `compose/` rule was hiding files in `svelte/src/components/compose/`. If you
  add ignore rules for new top-level dirs, anchor them.
- Binary artifacts `dockpal`, `dockpal-linux-amd64`, `.dockpal-dev` and data dirs
  `.data*` are gitignored; don't commit them.
- Release workflow (`.github/workflows/release.yml`) builds and embeds the frontend
  before compiling — skipping that makes the binary refuse to serve `/`.
